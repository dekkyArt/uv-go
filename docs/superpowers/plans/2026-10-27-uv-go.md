# UV GO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Статический сайт UV GO на Astro: React-остров приложения, которое находит лучшее время выйти на улицу, с насыщенным motion, «живым небом», темами, тремя SEO-статьями, How it works и FAQ.

**Architecture:** Astro (`output: 'static'`) рендерит страницы сайта без JS. Приложение — один React-остров `client:load` на `/`. Логика — чистый TypeScript в `src/domain/` (скоринг, окна, причина, чек-лист, небо) с конфигом правил `rules.config.ts`. Слой `src/data/` ходит в Open-Meteo и localStorage. Motion (`motion/react`) через `LazyMotion` + `domMax`.

**Tech Stack:** Astro (latest stable), React 19, TypeScript strict, Tailwind CSS v4, Motion, MDX, Vitest + Testing Library + jsdom, Playwright + axe, Lighthouse CI, GitHub Actions, Vercel.

**Spec:** `docs/superpowers/specs/2026-10-27-uv-go-design.md` — исполнитель читает ТЗ вместе с планом. Ссылки вида «ТЗ 6.4» указывают на разделы ТЗ.

## Global Constraints

- Сайт полностью статический: нет API routes, server actions, SSR по запросу (ТЗ 2).
- Все строки UI на английском; слова «safe», «perfect», «AI-powered» запрещены в UI, шаблонах и контенте (ТЗ 6.5, 11.3).
- Все пороги и числа правил — только в `src/domain/rules.config.ts`; в коде скоринга нет магических чисел (ТЗ 6).
- `src/domain/` не импортирует React, DOM, `src/data/`, `src/app/`.
- Всё время — в часовом поясе локации; `now` передаётся в domain параметром (ТЗ 7.3).
- Анимируются только `transform` и `opacity` (исключение — цвет маленьких элементов); `LazyMotion` + `m`-компоненты, никакого `motion.*` (ТЗ 10.1).
- Лучшее время читается ≤ 1.0 с после данных; первая хореография ≤ 1.8 с (ТЗ 10.1).
- Каждая анимация имеет поведение для `prefers-reduced-motion` по ТЗ 10.10.
- Контраст ≥ AA (текст 4.5:1, графика 3:1) в обеих темах при любой фазе неба; тач-цели ≥ 44×44 px (ТЗ 12.2).
- JS на `/` ≤ 130 KB gzip; JS на статьях ≤ 2 KB (ТЗ 12.1).
- Lighthouse mobile: Performance `/` ≥ 90, статьи ≥ 95; Accessibility ≥ 95; SEO = 100; Best Practices ≥ 95; LCP ≤ 2.5 с, CLS ≤ 0.05 (ТЗ 12.1).
- Каждое обращение к localStorage — в `try/catch`; ключи `uvgo:location`, `uvgo:inputs`, `uvgo:theme` (ТЗ 7.4).
- Нет cookies, аналитики, сторонних скриптов (ТЗ 12.4).
- Атрибуция «Weather data by Open-Meteo.com» со ссылкой в футере на всех страницах.
- Node 22 LTS, npm. Коммиты в стиле Conventional Commits.

## Review Focus

1. **Часовой пояс локации ≠ браузера и дни перехода на летнее/зимнее время** — пользователь ожидает часы локации, а в день DST у Open-Meteo бывает 23/25 записей; дни делятся по дате из `time`, а не по индексам. Тест: Task 9 `maps DST day by hour, filling gaps`.
2. **Полярный день/ночь (нет валидных `sunrise`/`sunset`)** — небо и дуга не должны ломаться: фаза по `isDay`, солнце в центре дуги. Тест: Task 8 `falls back to isDay when sunrise/sunset invalid`.
3. **Быстрый набор в поиске города** — поздний ответ на старый запрос не должен перезаписать результаты нового. Тест: Task 11 `ignores out-of-order responses`.
4. **Испорченный или старый localStorage** (невалидный JSON, `duration: 45`, чужая форма) — приложение стартует на значениях по умолчанию без ошибок. Тест: Task 10 `drops invalid stored inputs field by field`.
5. **Вкладка открыта через смену часа или полночь** — прошедшие часы должны гаснуть, а после полуночи «Today» — подгружаться заново. Тесты: Task 11 `useNow ticks every minute`, `isForecastStale`.
