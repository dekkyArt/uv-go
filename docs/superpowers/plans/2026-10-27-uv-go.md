# UV GO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static UV GO site built with Astro: a React application island that finds the best time to go outside, with rich motion, a “living sky,” themes, three SEO articles, How it works, and FAQ.

**Architecture:** Astro (`output: 'static'`) renders site pages without JS. The application is a single React island `client:load` on `/`. Logic is pure TypeScript in `src/domain/` (scoring, windows, reason, checklist, sky) with rules configuration `rules.config.ts`. The `src/data/` layer accesses Open-Meteo and localStorage. Motion (`motion/react`) via `LazyMotion` + `domMax`.

**Tech Stack:** Astro (latest stable), React 19, TypeScript strict, Tailwind CSS v4, Motion, MDX, Vitest + Testing Library + jsdom, Playwright + axe, Lighthouse CI, GitHub Actions, Vercel.

**Spec:** `docs/superpowers/specs/2026-10-27-uv-go-design.md` — The implementer reads the specification alongside the plan. References such as “Spec 6.4” point to specification sections.

## Global Constraints

- The site is fully static: no API routes, server actions, or on-demand SSR (Spec 2).
- All UI strings are in English; the words “safe,” “perfect,” and “AI-powered” are prohibited in UI, templates, and content (Spec 6.5, 11.3).
- All rule thresholds and numbers belong only in `src/domain/rules.config.ts`; no magic numbers in scoring code (Spec 6).
- `src/domain/` does not import React, DOM, `src/data/`, `src/app/`.
- All times use the location's time zone; `now` is passed to domain as a parameter (Spec 7.3).
- Animate only `transform` and `opacity` (exception: the color of small elements); `LazyMotion` + `m` components, no `motion.*` (Spec 10.1).
- The best time is readable ≤ 1.0 s after data arrives; initial choreography ≤ 1.8 s (Spec 10.1).
- Every animation has behavior for `prefers-reduced-motion` per Spec 10.10.
- Contrast ≥ AA (text 4.5:1, graphics 3:1) in both themes at every sky phase; touch targets ≥ 44×44 px (Spec 12.2).
- JS on `/` ≤ 130 KB gzip; JS on articles ≤ 2 KB (Spec 12.1).
- Lighthouse mobile: Performance `/` ≥ 90, articles ≥ 95; Accessibility ≥ 95; SEO = 100; Best Practices ≥ 95; LCP ≤ 2.5 s, CLS ≤ 0.05 (Spec 12.1).
- Every localStorage access is wrapped in `try/catch`; keys `uvgo:location`, `uvgo:inputs`, `uvgo:theme` (Spec 7.4).
- No cookies, analytics, or third-party scripts (Spec 12.4).
- “Weather data by Open-Meteo.com” attribution with a link in the footer on every page.
- Node 22 LTS, npm. Use Conventional Commits.

## Review Focus

1. **Location time zone ≠ browser time zone and daylight-saving transition days** — The user expects local hours, while Open-Meteo may return 23/25 entries on a DST day; split days by the date in `time`, not by indices. Test: Task 9 `maps DST day by hour, filling gaps`.
2. **Polar day/night (no valid `sunrise`/`sunset`)** — The sky and arc must remain functional: derive the phase from `isDay`, place the sun at the arc's center. Test: Task 8 `falls back to isDay when sunrise/sunset invalid`.
3. **Fast typing in city search** — A late response to an old request must not overwrite newer results. Test: Task 11 `ignores out-of-order responses`.
4. **Corrupt or old localStorage** (invalid JSON, `duration: 45`, unexpected shape) — The application starts with defaults without errors. Test: Task 10 `drops invalid stored inputs field by field`.
5. **Tab stays open across an hour change or midnight** — Past hours must dim, and “Today” must reload after midnight. Tests: Task 11 `useNow ticks every minute`, `isForecastStale`.
